# Marketing video script best practices

## Structure

1. **Hook in the first 5 seconds.** Open with something the viewer already knows or
   cares about (a shared cultural touchpoint, a surprising number, a sharp question).
   Never open with the company name or "In today's fast-paced world".
2. **One video, one message.** Everything that doesn't serve it is cut. State the message
   in one sentence before drafting; the closing line should be its echo.
3. **Problem before product.** Spend roughly a third of the runtime making the problem
   concrete and felt, before introducing the solution. The solution reveal is a turn
   ("At <brand>, we saw an opportunity...").
4. **Rule of three.** Max three capabilities/benefits, each with one proof point or visual.
   Close with a line that unites them ("Speed. Quality. Cost. One connected...").
5. **Show the number.** Quantify the pain, then the outcome, then the value. Make the
   big figure the on-screen hero and put its working underneath in small text.
6. **Expand, then land.** After the proof, widen the lens ("And why stop at X?"), then
   end on a benefit-led tagline and a brand lockup, not a feature list.
7. **Clear CTA.** Say what the viewer should do next, or end on an explicit brand
   promise if the video is awareness-only.

## Voice-over

- Write for the ear: short sentences, contractions, active voice, one idea per line.
- Vary rhythm: pair a long setup with a short punchline ("Same product. Very different needs.").
- Use light, confident wit and direct address sparingly; one wry aside per act at most.
- Use parallel triplets for emphasis ("Beginners. Explorers. Speedrunners.").
- Read it aloud; if you run out of breath or stumble, rewrite.
- Pace: ~150-170 words/min; leave breathing room around key numbers.
- Avoid buzzword stacking (leverage, synergy, cutting-edge, next-gen, revolutionary).
  Replace with the concrete thing the product does.
- Name specifics: real behaviours, real artefacts, real numbers.
- Default to plain language a layman follows on first hearing. Replace jargon with
  everyday words or a one-line analogy ("a skill is your team's recipe, saved"),
  explain any unavoidable term once, and keep technical detail for the notes.
  Only go technical if the brief names a technical audience.

## On-screen text

- Reinforce, don't transcribe. Headline is the takeaway of the beat.
- UPPERCASE, <= 8 words, one idea. Big numbers get their own frame.
- Keep text on screen long enough to read twice (word count / 3 seconds minimum).
- Design for sound-off viewing: the headline sequence alone should tell the story.

## Visuals

- Visual metaphor should come from the audience's world (e.g. a game world to
  explain testing). Pick one world and stay in it.
- Each row has one clear change on screen (appear, transform, pull back, reveal).
- Alternate illustrative animation with real product/engineering footage to build
  credibility; specify which is which.
- Transitions carry meaning (matrix becomes agent sessions; hours become dollars).
- Brand sign-off with a signature sound or sting.

## Claims, honesty and compliance

- Source every real statistic; label every model "illustrative".
- Never present potential value as achieved savings. Say "potential", "target", "assumed".
- Disclose key assumptions in production notes (rate, reduction %, volumes) and
  what the figure excludes (e.g. solution costs).
- Customer/partner references only if confirmed; keep portfolio footage separate from
  delivery claims.
- Third-party IP (logos, game titles, music): note rights/permissions needed.

## Pre-delivery checklist

- [ ] Hook lands in the first 5 s and isn't the brand name
- [ ] Single message stated; closing line echoes it
- [ ] Problem takes ~1/3 of runtime; solution is a clear turn
- [ ] <= 3 capabilities, each with a proof point
- [ ] Hero number on screen with its working shown in small text
- [ ] Every VO line speakable in one breath; word count fits runtime at ~160 wpm
- [ ] On-screen text reinforces, <= 8 words, readable sound-off
- [ ] Every Visual cell is a directable, single-change instruction
- [ ] All maths re-computed and consistent across rows and notes
- [ ] Illustrative figures labelled on screen and in notes
- [ ] Every real fact has a source; unsourced numbers are placeholders
- [ ] Ends on benefit-led tagline + brand lockup + sign-off sound
